💡 Key Lessons

Why Memory Leaks Happen

  • Forgotten Subscriptions: Observables like interval, fromEvent, or HTTP requests keep running unless unsubscribed.
  • Closures: Callbacks (e.g., in setInterval) retain references to the component, preventing garbage collection.
  • Async Pipes: The async pipe in templates auto-unsubscribes, but manual subscriptions (e.g., in `.subscribe()`) do not.

How to Prevent Leaks

  • takeUntil: Use a Subject (e.g., destroy$) to unsubscribe in ngOnDestroy.
  • async Pipe: Prefer it in templates (auto-cleanup).
  • Unsubscribe Manually: Store subscriptions and call unsubscribe() in ngOnDestroy.
  • Linting: Use ESLint rules like rxjs-no-unbounded-observables to catch leaks.

RxJS Operators Used Here

  • debounceTime(300): Waits 300ms after the last keystroke.
  • distinctUntilChanged(): Skips duplicate values.
  • switchMap: Cancels previous requests if a new one comes in.
  • takeUntil: Unsubscribes when destroy$ emits.
  • tap: Side effects (e.g., setting isSearching).
